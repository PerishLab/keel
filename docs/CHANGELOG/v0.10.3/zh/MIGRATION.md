# 迁移到 Keel v0.10.3

对不声明闭包的调用方没有任何要求。公开表面只增不减:`closure` 是新增修饰符,
不使用它的代码在 v0.10.3 上的编译与行为与 v0.10.2 完全相同。

存储格式从十一升到十二,所以既有库会在首次打开时演进。那是 Keel 本就会做的那次演进,
现在它还会在同一事务内刷新派生关系,因此没有额外步骤要跑,也不存在「schema 已变、
闭包未建」的窗口。没有库需要重建,也不丢数据。

如果你要在既有 bond 上采用 `closure`,动手前有两件事值得知道。其一,从那时起任何会形成环的
联系都会被拒绝,所以当前含环的图会开始拒绝造环的写入——**先确认数据无环**,
因为失败发生在写入时而不是声明时。其二,生成的 `<bond>_closure` 关系归引擎所有,
直接写入会被拒绝,所以此前自己维护同名可达性表的代码必须停止写入 derive 现在占用的这个名字。
