# Keel v0.10.4

## 建行不再铸一份已有 grant 覆盖着的权限

操作者的每一次写入原本都会再写一行:一条 `@grant`,把刚建好的东西完整地授给创建者。
现在只有当创建者已持有的任何东西都覆盖不到这一行时,才写这条 grant。

它从来不是免费的,而且代价不止那一行。写 `@grant` 会 bump 该单元的世代,
于是下一次授权检查要重读整张 grant 表 —— 而那张表刚刚因为这次铸多了一行。
**建行因此是二次的**,授权账本永久地按数据行数增长。

随本次发布附上的读数
(`cargo test -p keel --test cost -- --ignored --nocapture --test-threads=1`),
内存 SQLite、每轮三百次写:

    轮次   改前 put   改后 put   改前 grants   改后 grants
    1      0.92ms     0.20ms     303           3
    3      2.67ms     0.20ms     903           3
    6      6.23ms     0.22ms     1803          3

而不铸的写(`set`)在改前改后都稳定在 0.24ms。**这一对就是全部结论**:
授权检查从来不是贵的那一半,铸才是;而正是铸让检查变贵。

判定规则是 Keel 已有规则的镜像。操作者签不出的 grant 会被拒绝;
**同理,只是重复它已持有覆盖的 grant 什么也不携带,于是不写**。
匿名身份诞生保留无条件铸,因为新生的身份还什么都不持有。

## 一次写入由它开始时的状态授权

行覆盖与子树覆盖现在按 `set` **动手之前**的状态判定。
谓词仍然前后都要成立,因为谓词描述的是这一行的内容,写入不得使它变假。

这一条是被上一条逼出来的,不是并列的选择。经由根链覆盖一行的持有者,
之前之所以能把它交给别人,靠的正是铸给他的那份**与根链无关**的行覆盖:
改动后的检查会重新沿链锚定,而移交之后这一行已挂在接收者名下。
**交接恰恰是那种「做完我就够不着了」的写入**,要求做完之后还够得着,等于永远禁止交接。

「抢」不受影响:够不着的行在**先**跑的那次检查就被拦下 —— 那道检查一直在干活。

## 写入成功但你已看不见时,回 204

`PATCH` 原本在写完之后用同一个操作者的身份把行读回来,读不到就报 `404` ——
而那时写入**已经发生**。现在这种情况回 `204 No Content`。
`404` 保持它一贯的含义:什么都没写。

## `allows` 退出文档

`DESIGN.md` 与 `ARCHITECTURE.md` 都描述过一个非变更性的探针,
但没有任何 `Face` 实现它,也没有任何测试调用它。
根投影的封印所声称的是「有人读过两边」,所以代码不兑现的承诺应当移除而不是留着。
若确实需要这个探针,它可以带着自己的测试再来。

## 底下的改动

`check`、`shift`、`spans`、`broad` 本是一个接收者披着四张皮,现在是 `Court`;
一条 deed 被要求判定的东西是一个 `Case`。
