# 迁移到 Keel v0.10.4

本次发布改变了授权行为。**升级前请读完** —— 其中两条对调用方可见,一条对客户端可见。

**不动存储。** 格式未变,首次打开不演进,不重写任何数据。
早先版本铸出来的 grant 行原样留着:它们现在是**冗余**而不是**错误**,
在并集语义下继续生效;**本次发布不附带任何清扫**。
估算若想清掉它们,可以在自己决定之后把它们当普通行 end 掉。

## 你「靠建行获得」的覆盖可能不再存在

改前:建行总是铸给创建者对该行的完整覆盖。
改后:只有当创建者已持有的任何东西都覆盖不到这一行时,才写这条 grant。

**如果你依赖的覆盖正是当初让你建行的那一份**(子树 grant、`all` 范围、
或仍然匹配的谓词),你不受影响——你建的行仍然经由它可达。

**如果你依赖「建出来的行活得比那份覆盖更久」,你受影响。**两种形态要检查:

- 某个操作者在一份你后来会撤销或收窄的 grant 下建行。改前他保留自己建的每一行;
  改后他随那份 grant 一起失去它们。**若那份访问本就该长存,请显式签一条 grant** ——
  它本来就是这个意思,只是从没写下来。
- 某个操作者在**只覆盖 `put` 的谓词** grant 下建行。这里没有变化:
  谓词只覆盖一个动词,所以它覆盖不到新行的 `see` / `set` / `end`,铸照旧发生。
  如果你一直靠着这次铸,它仍然在你脚下 —— 但值得想清楚,你是否本来就想授出那几个动词。

**如果你把 pulse 流里的 `@grant` put 当作「有人建行了」的信号**,
对「已被覆盖的建行」这个信号没有了。请改为盯你真正关心的那个单元。

## 把一行交给别人现在可行,而且交完你就够不着了

把一行移出自己子树的 `set`,改前会被拒绝,除非你持有与根链无关的行覆盖 ——
实践中就是铸塞给你的那一份。改后它成功,而且**之后这一行不再属于你**。

「抢」没有被放松:够不着的行仍然在写入**之前**那次检查失败。
变的只是:「给出去」不再被写入**之后**那次检查禁止。

**如果你的产品是靠这条拒绝来禁止转让的,那它现在不再被引擎禁止。请改用 grant 表达。**

## 写入者已看不见时 `PATCH` 回 204

该路由写完之后用同一个操作者读回,读不到就报 `404` —— 于是**为一次已经成功的写入报告了失败**。
现在这种情况回 `204 No Content`。

把所有非 2xx 一律当失败的客户端,此前在这里本就是错的,现在恰好对了;
把 `404` 理解成「这次写入没有发生」的客户端,现在是对的:
`PATCH` 的 `404` 意味着什么都没写。

## `allows` 从来没有被实现过

`DESIGN.md` 与 `ARCHITECTURE.md` 描述过一个非变更性的 `allows` 探针,
但没有任何 `Face` 暴露过它。相关句子已删除。**没有代码变更,因为本就没有代码。**

## 这次升级值多少

**写入不再随估算规模变慢。** 按随本次发布附上的读数:
一次会铸的写在估算积累到 1800 条 grant 的过程中从 0.92ms 涨到 6.23ms;
升级之后同样的写在任何规模上都是 0.20ms,而授权账本**不再跟踪数据量**。
